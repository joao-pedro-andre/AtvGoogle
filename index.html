ETAPA 01 · FUNDAMENTOS

O que é autenticação com Google?

É uma forma de permitir que uma pessoa entre em uma aplicação usando uma conta Google, sem precisar criar uma senha nova no seu site. O Google confirma a identidade e fornece um ID token, que será validado pelo backend.

◎Google Identity

Exibe a interface de login e retorna uma credencial após a autenticação.

⌘Backend Node.js

Recebe e verifica a credencial antes de confiar nos dados do usuário.

◈Sessão

Mantém o usuário autenticado nas próximas requisições.

Importante

O frontend nunca deve considerar um usuário autenticado apenas porque recebeu um nome ou e-mail. A validação do token precisa acontecer no servidor.

ETAPA 02 · VISÃO GERAL

Como funciona o processo?

O fluxo pode ser dividido em seis momentos. Cada parte tem uma responsabilidade específica:

1
Usuário clica em “Entrar com Google”

O botão é apresentado pelo Google Identity Services.

2
Google autentica a conta

Após a confirmação, o Google devolve um ID token ao navegador.

3
Frontend envia o token à API

A credencial é enviada por HTTPS em uma requisição POST.

4
Backend valida o token

O servidor confere assinatura, emissor, público e validade.

5
Servidor cria uma sessão

Um cookie HttpOnly é enviado ao navegador.

6
Área autenticada é liberada

A aplicação consulta a sessão e exibe o conteúdo protegido.

ETAPA 03 · CONFIGURAÇÃO

Configurando o Google Cloud

Para usar o Login Google, é necessário criar um projeto no Google Cloud e configurar a tela de consentimento e o cliente OAuth.

  1. Acesse o Google Cloud Console e crie ou selecione um projeto.
  2. Configure a tela de consentimento OAuth, informando o nome do aplicativo e os dados solicitados.
  3. Crie um ID do cliente OAuth do tipo Aplicativo da Web.
  4. Em origens JavaScript autorizadas, adicione o endereço local usado no desenvolvimento e o domínio publicado.
  5. Guarde o Client ID. Ele pode ser público no frontend; segredos devem permanecer no servidor.
Atenção aos domínios

Em produção, cadastre exatamente o domínio usado pela aplicação. Endereços diferentes, como localhost e o domínio da Vercel, precisam ser configurados separadamente.

ETAPA 04 · NAVEGADOR

Integrando o botão no frontend

O Google Identity Services disponibiliza a biblioteca que renderiza o botão e executa o fluxo de autenticação. No HTML, carregamos o script oficial:

HTML · carregar a biblioteca
<script src="https://accounts.google.com/gsi/client" async defer></script>

Depois de obter o Client ID da configuração do servidor, inicializamos a biblioteca e recebemos a credencial no callback:

JavaScript · inicialização simplificada
google.accounts.id.initialize({
  client_id: config.clientId,
  callback: ({ credential }) => {
    enviarTokenParaAPI(credential);
  }
});

google.accounts.id.renderButton(
  document.getElementById("google-button"),
  { theme: "outline", size: "large" }
);

A função enviarTokenParaAPI deve encaminhar o token ao backend. Não use os dados recebidos diretamente para liberar áreas protegidas.

ETAPA 05 · SERVIDOR

Validando a credencial no backend

O backend usa a biblioteca google-auth-library para verificar se o token foi realmente emitido para o Client ID da aplicação.

Node.js · exemplo de validação
const { OAuth2Client } = require("google-auth-library");

const client = new OAuth2Client(process.env.GOOGLE_CLIENT_ID);

async function validarToken(idToken) {
  const ticket = await client.verifyIdToken({
    idToken,
    audience: process.env.GOOGLE_CLIENT_ID
  });

  const usuario = ticket.getPayload();

  if (!usuario.email_verified) {
    throw new Error("E-mail não verificado");
  }

  return usuario;
}
Por que validar no servidor?

Porque informações enviadas pelo navegador podem ser alteradas. A verificação criptográfica permite confirmar que a credencial é válida e destinada à sua aplicação.

ETAPA 06 · SEGURANÇA

Criando e verificando uma sessão

Depois da validação, o servidor cria uma sessão própria. Neste projeto, ela é representada por um cookie com as proteções adequadas:

  • HttpOnly: impede que scripts do navegador leiam o cookie diretamente.
  • Secure: envia o cookie somente por HTTPS em produção.
  • SameSite: ajuda a reduzir o envio indevido do cookie em outros contextos.
  • Expiração: limita por quanto tempo a sessão permanece válida.
HTTP · exemplo de cookie
Set-Cookie: app_session=TOKEN_ASSINADO;
  HttpOnly; Secure; SameSite=Lax; Path=/

Nas próximas visitas, o frontend consulta uma rota como /api/auth/me. O servidor verifica o cookie e responde se existe uma sessão válida. Ao sair, a rota de logout encerra a sessão.

ETAPA 07 · FINALIZAÇÃO

Testando e publicando

Antes de considerar a implementação concluída, confira os pontos abaixo:

  • O botão do Google aparece sem erros no console.
  • O login válido cria uma sessão no servidor.
  • Atualizar a página mantém a sessão enquanto ela for válida.
  • Uma sessão inexistente ou expirada não libera o conteúdo protegido.
  • O botão “Sair da conta” encerra a sessão e retorna à tela de login.
  • As variáveis de ambiente estão configuradas no painel da hospedagem.
